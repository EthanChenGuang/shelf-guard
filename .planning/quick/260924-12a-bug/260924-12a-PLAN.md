<objective>
Fix a bug where, during the guided first-baseline capture flow, tapping the shutter button
still shows/saves the bundled demo/test shelf image (`/demo-shelf.jpg`) instead of a real photo
taken with the device camera.

Purpose: The guided first-baseline flow is the very first thing a new shelf owner does in
ShelfGuard. If it silently persists the demo image as the "baseline," every future diff for
that shelf compares real photos against a stock stock-photo baseline — the core comparison
feature is broken from day one for that shelf.

Output: `src/App.tsx` automatically requests the live device camera the moment a shelf enters
the first-baseline guide (`INITIAL_GUIDE`) while still on the demo feed, so by the time the
user taps the shutter, `captureFrame()` draws from the live `<video>` element instead of
redrawing the demo image. A regression test proves the fix and guards against re-regression.
</objective>

# Root cause (confirmed by reading the live implementation, not notes):
#
# 1. `src/hooks/useCameraStream.ts` defaults `isUsingDemoFeed = true` — "default to
#    high-res demo shelf feed so user sees instant live planogram!" — and ONLY flips to
#    `false` via an explicit user tap on the "使用真实摄像头" pill
#    (`onToggleDemoMode` -> App.tsx `handleEnableLiveCamera` -> `startCamera()`).
#
# 2. `captureFrame()` in the same file branches on `isUsingDemoFeed`:
#    - `false` (real camera): draws the live `<video>` frame to canvas — a real photo.
#    - `true` (demo feed, the default): calls `captureDemoFrameFromUrl(baselineImageUrl)`,
#      which just re-draws whatever `baseline.imageDataUrl` currently is onto a canvas and
#      returns that as the "captured frame." For a shelf with no baseline yet, that URL is
#      still `DEFAULT_CALIBRATION.imageDataUrl` = `DEFAULT_SHELF_IMAGE_URL` =
#      `/demo-shelf.jpg` (`src/lib/constants.ts`) — the bundled test image.
#
# 3. `src/components/InitialGuideOverlay.tsx`'s 3-step guide never calls `startCamera()`.
#    Its final "拍摄基准图" button only calls `onComplete` -> App.tsx
#    `onDismissInitialGuide` -> `setAppMode('CAMERA_IDLE')`. The physical shutter button
#    underneath (`CameraView.tsx` `handleShutterClick` -> App.tsx `handleShutterClick`,
#    lines ~252-323) is what actually captures — and it never checks or changes
#    `isUsingDemoFeed` either.
#
# 4. Net effect: nothing in the guided first-baseline path ever requests real camera
#    access. `isUsingDemoFeed` stays `true`, so `handleShutterClick`'s
#    `captureFrame(baseline.imageDataUrl)` takes the demo-redraw branch and the "captured"
#    baseline is literally the demo/test image, which is exactly the reported symptom.
#
# App.tsx already has the correct activation path for this, just never wired into the
# guide: `handleEnableLiveCamera` (line ~488) calls `startCamera()` and, on success,
# `requestOrientationPermission()` — currently only reachable via the manual toggle pill.
