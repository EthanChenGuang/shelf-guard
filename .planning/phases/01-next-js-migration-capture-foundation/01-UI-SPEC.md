## Phase 1 UI Surfaces

### 1. Camera Error Inline Banner (CAM-08, D-07–D-09)

**Placement:** Inside `CameraView`, in bottom control column (`relative z-20 pb-8`), **above** the shutter prompt pill, full width within `px-6`.

**Visibility:** Render when `cameraError !== null` (passed from `useCameraStream` via `App.tsx`). Banner persists after fallback to demo feed so user understands why Cam mode failed.

**Layout:**
```
┌─────────────────────────────────────┐
│ [AlertCircle] Headline              │
│ Body text (iOS guide, 2–3 lines)    │
│ [Try Camera Again]  [Dismiss ✕]     │
└─────────────────────────────────────┘
```

**Styling:**
- Container: `mb-4 w-full max-w-sm rounded-2xl border border-amber-500/40 bg-[#0F172A]/90 backdrop-blur-md px-4 py-3 shadow-lg`
- Icon: `AlertCircle` from lucide, `w-4 h-4 text-amber-400`, `flex-shrink-0`
- Headline: `text-xs font-semibold text-white`
- Body: `text-[10px] font-medium text-white/80 leading-relaxed mt-1`
- Actions row: `mt-3 flex items-center gap-2`
  - Retry: `text-[11px] font-semibold text-emerald-400 hover:text-emerald-300` — calls `onRetryCamera` (re-invokes `startCamera`)
  - Dismiss: icon-only `X` button, `w-8 h-8 rounded-full hover:bg-white/10`, clears `cameraError` via `onDismissCameraError`

**Interaction:** Banner does **not** block demo/camera toggle or shutter when in `CAMERA_IDLE`. User can switch to Demo via existing top-bar toggle without dismissing.

**New props on `CameraView`:**
- `cameraError: string | null`
- `onRetryCamera: () => void`
- `onDismissCameraError: () => void`

---

### 2. Shutter Double-Tap Guard (STAB-01, D-16)

**Behavior:** `onShutterClick` ignored when `appMode` is `SCANNING_ANIM` or `PROCESSING`, or when `isCaptureLocked === true` (ref in `App.tsx`).

**Visual feedback (locked state):**
- Shutter button receives `disabled` + `aria-disabled="true"` + `aria-label={t.shutterLocked}`
- Classes added: `opacity-50 cursor-not-allowed pointer-events-none`
- Remove breathing ping: hide `animate-ping` ring sibling when locked
- Shutter prompt pill copy unchanged (still `tapShutterToScan`) — lock state communicated via shutter affordance + aria only

**Unlock:** When FSM returns to `CAMERA_IDLE` or `RESULT_INSPECT` completes and returns to camera.

---

### 3. Torch Button Honesty (STAB-02, D-17)

**Behavior:** Export `hasTorch: boolean` from `useCameraStream` — set `true` only when active video track reports `'torch' in track.getCapabilities()`. On constraint failure, do **not** flip `isTorchOn`.

**UI rule:** **Hide** torch button entirely when `hasTorch === false` OR `isUsingDemoFeed === true`. Do not render disabled placeholder in Phase 1 (keeps top-bar compact).

**When visible:** Same styling as today — `w-7 h-7 rounded-full`; active state `bg-[#10B981] text-white`.

**Hook change:** Remove demo/no-stream fallthrough that toggles `isTorchOn` without hardware (`useCameraStream.ts:56-57, 76`).

---

### 4. PROCESSING State UI (STAB-03, D-15)

**FSM:** After shutter, `SCANNING_ANIM` for 800ms. If analysis Promise unresolved at 800ms, transition to `PROCESSING`. When analysis completes, go to `RESULT_INSPECT`.

**Component:** Extend `ScanningAnimationOverlay` with prop `variant: 'scanning' | 'processing'` (default `'scanning'`).

| Variant | Frozen frame | Beam animation | Status pill copy | Icon |
|---------|--------------|----------------|------------------|------|
| `scanning` | yes | 0.8s scan beam + shutter flash | `t.scanning` | `Sparkles` spin |
| `processing` | yes | **Static** subtle pulse overlay (`bg-[#38BDF8]/10 animate-pulse`) — no scan beam | `t.processing` | `Loader2` spin (`w-4 h-4 text-[#38BDF8]`) |

**Render in `App.tsx`:**
```tsx
{(appMode === 'SCANNING_ANIM' || appMode === 'PROCESSING') && (
  <ScanningAnimationOverlay
    lang={lang}
    frozenFrameUrl={capturedFrame}
    variant={appMode === 'PROCESSING' ? 'processing' : 'scanning'}
  />
)}
```

**Z-index:** `z-50` full-screen overlay — blocks all interaction during scan/processing (shutter lock redundant but kept for early taps).

### 5. Offline Indicator Verification (PWA-03)

**Existing component:** `OfflineIndicator` — fixed `bottom-3 left-4 z-50`.

**Phase 1 changes:**
- Move hardcoded bilingual string to `I18N[lang].offlineMode`; pass `lang` prop from `App.tsx`
- Verify visibility: `navigator.onLine === false` → show; `online` event → hide
- **Stacking:** Offline pill stays `bottom-3 left-4`. Camera error banner lives inside `CameraView` bottom column (higher in stack) — no overlap at default viewport. If both visible, offline remains below error banner vertical space.

**Styling (unchanged):** `rounded-full bg-amber-600/90 backdrop-blur-md px-3 py-1.5 text-xs font-medium text-white shadow-lg border border-amber-400/30` + `WifiOff` icon.

**Post-deploy verification:** Manual test on Vercel preview — DevTools → Network → Offline → pill appears within one frame of `offline` event.
